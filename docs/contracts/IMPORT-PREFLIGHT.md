# 2026 合同登记表只读预检

## 来源核验

- 核验文件：资料包 `源数据/2026年合同登记表.xlsx`
- 当前文件 SHA-256：`e21fbebee1a061eb7f504cfe41cf1c4de42fd1a7bf0ebbe1575af0f6f8b0e8dc`
- 当前工作簿共 3 个工作表：`2026物化院`、`2026六院`、`2026测绘院`。
- 业务方于 2026-09-24 确认：当前只能提供带表头的版本，该文件不是正式历史数据源。
- 先前资料包版本的哈希和工作表数量与当前文件不同，只保留为设计资料版本差异，不作为当前数据证据。

## 与分析报告的差异

现有工作簿中有 3 行在结构上同时占用了合同编号列和项目名称列：`2026物化院`、`2026六院`、`2026测绘院`各 1 行。业务方已确认当前文件只是带表头的版本，因此这 3 行只能用于检验列映射，不能认定为真实合同记录。分析报告所述 106 + 1 + 46 = 153 行也无法由当前文件复现。

因此，本期正式可导入记录数为 0；“153 条”和结构上识别出的 3 行都不得作为导入验收基线。原始数据当前无法提供，历史导入保持阻断，不影响新业务数据手工录入。

## 已实现的预检规则

- 按工作表维护显式字段映射，不按列名或部门名称猜测稳定标识。
- 候选行要求合同编号和项目名称；缺失时给出工作表及行号错误。
- 合同编号先做 Unicode 兼容归一、移除空白并转大写，用于查重；原值仍保留在预览结果。
- 来源金额按“万元”乘以 10,000 转换为“元”，无法解析时定位到源行。
- 幂等键由源文件哈希、工作表、行号和规范化合同编号共同生成。
- 命令默认不输出真实业务字段；只有显式加入 `--include-values` 才在本机终端显示预览值。
- 预检全程只读，不连接数据库、不生成正式导入批次。
- `--template-only` 模式只验证工作表和字段结构，并强制把可导入记录数置为 0。

运行方式：

```powershell
pnpm --filter @safety/api contract-import:preflight -- "<xlsx 路径>" --template-only
```
