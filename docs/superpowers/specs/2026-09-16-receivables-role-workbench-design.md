# 应收账款角色化异常处置台设计

日期：2026-09-16

状态：用户已批准

## Direction Contract

**THESIS**

应收账款首页不是统计陈列墙，而是从权威金额进入异常处置和催收行动的工作台。

**OWN-WORLD**

沿用主系统现有浅色 Ant Design 管理界面、蓝色主操作、紧凑侧栏和服务端权限语义；不建立第二套品牌、图标语言或陌生交互。

**STORY**

用户先确认当前权限和筛选范围内的应收余额，再识别异常或催收工作，随后按债权状态或单位缩小范围，最终进入同一台账处理或查看。

**FIRST VIEWPORT**

应收余额必须是最大、最高对比度的事实；三个异常处置入口在桌面端与其并列，在手机端紧随其后。每个入口都必须带当前筛选条件进入台账。角色标题、说明、主操作和右侧工作区必须反映财务维护、催收维护或只读查看的实际能力。

**FORM**

Code-led。首屏以深蓝权威金额面板、克制的橙色异常数字和浅色行动列表组成；债权状态与单位分布作为第二层。表单、按钮和焦点状态继续使用现有控件。窄屏单列且不得与折叠菜单按钮碰撞。概念轮种子：`a4e1a582`，用户锁定候选 3“异常处置台”。

**QUALITY BAR**

本规格即本轮质量基准：五秒内识别应收余额、风险数量和下一步入口；不同 capability 不出现越权动作暗示；所有可点击分类都产生真实筛选；桌面和 390px 手机宽度无遮挡或横向溢出。

## 目标

把现有“应收账款看板”改造成可操作的异常处置台，同时保留现有台账、数据处理、权限和配置页面。首页不再平铺八张同权重统计卡，而是先回答“有多少钱、哪里有风险、下一步去哪里处理”。

## 角色化首页

- 负责人和财务管理员：优先显示应收余额、到账金额、待核对事项、债权状态和单位分布，并提供财务数据处理入口。
- 拥有金额维护能力的财务人员：优先显示金额待补充、超收和核销待调整事项，入口直接落到相应筛选后的台账。
- 报账员：优先显示其权限范围内的应收余额和催收入口；有催收维护权限时，首页明确引导其进入台账更新催收字段和附件。
- 只读人员：保留风险与金额概览，只提供查看入口。

角色文案与入口只消费服务端返回的 capability，不在前端推断组织身份。

## 页面结构

1. 顶部标题区显示与当前 capability 对应的工作台名称、说明和主操作。
2. 首屏使用一张重点金额面板展示应收余额，并以到账、开票、有效台账作为辅助指标。
3. “需要处理”区域展示决算未定、超收、核销待调减三个既有异常计数；点击后进入带相同服务端筛选条件的台账。
4. 下方展示债权状态和单位记录分布；点击某项进入已筛选的台账。
5. 原有记录状态分布从首页移除，因为首页默认已筛选有效、未结记录，该分布不能帮助处置。
6. 筛选区保留记录状态、结清状态和待核对事项，改成紧凑工具条。

## 数据与权限

- 复用现有 dashboard 金额与异常聚合，在响应中补充债权状态和单位 facet，不新增表或统计引擎。
- 台账页从 URL 读取受支持的 `status`、`settlement`、`anomaly`、`debtStatus` 和 `creditorUnit` 初始筛选；非法值回退到现有默认值。
- 所有聚合、计数和列表继续受服务端财务范围约束；URL 参数不扩大权限。
- 不引入未经确认的“久未催收天数”阈值，也不把债权状态自动解释成逾期规则。

## 视觉与交互

- 沿用主系统现有浅色界面、Ant Design 控件和蓝色主操作，不创建第二套品牌。
- 用层级、留白、数字排版和克制的风险色区分重点，不使用装饰性渐变、玻璃拟态或无意义动画。
- 桌面端重点金额与待办并排；窄屏改为单列。所有卡片入口具备键盘焦点和明确按钮文本。

## 非目标

- 本轮不新增财务员工技术角色或改变服务端授权模型。
- 本轮不修改金额、催收、附件的写入接口和审计规则。
- 本轮不建设目标回款率、趋势图、自动逾期、催收提醒或消息中心。
