# 人员与组织管理工作台改版设计

## 目标

将当前“人员档案、账号与权限、身份绑定申请、组织与项目”混合且重复的页面，整理成以人员为主线、以组织为授权入口、以审核中心承接流程的统一工作台。改版只调整信息架构和前端交互，复用现有人员、账号、组织、项目、角色、申请、导入和审计模型，不改变培训教育等其他业务模块。

## 已确认的信息架构

人员与组织管理模块保留五个日常入口：

1. 人员档案
2. 组织与职责
3. 项目与成员
4. 审核中心
5. 数据工具

公司管理员额外看到“账号异常处理”。取消独立的“账号与权限”人员总表；账号是人员的登录身份，日常账号操作归入人员详情。

## 人员档案

- 默认显示可搜索的平铺人员列表，不再默认将所有人员隐藏在折叠部门中。
- 支持姓名、手机号、用户名和工号搜索；支持组织、人员状态、账号状态和管理角色筛选。
- 提供“列表视图 / 按部门分组”切换，并保存个人偏好。
- 点击姓名进入独立详情路由，刷新页面和复制链接后仍能打开同一人员。
- 批量操作仅在勾选人员后出现。
- 人员详情包含：基本档案、账号与登录、组织与权限、项目关系、证照、培训记录、申请与变更、操作记录。
- 停用人员、停用账号、解除微信、账号合并和误建档案清理集中放在“谨慎操作”区域。

## 账号管理

- 无账号：显示“开通账号”。
- 待激活：显示等待事项、创建时间和“取消开通”。
- 正常：显示重置密码、修改用户名、管理登录方式和停用账号。
- 已停用：显示停用原因、时间和重新启用。
- 已合并：只读显示合并目标和历史，不允许重新启用。
- 疑似重复、绑定冲突和长期待激活进入公司管理员的“账号异常处理”队列。
- 公司管理员创建后台账号时输入用户名和两次临时密码；首次登录必须修改临时密码。
- 所有操作继续使用服务端权限与生命周期校验，前端不自行推断授权。

## 组织与职责

- 使用“左侧组织目录＋右侧工作台”，组织列表不分页。
- 左侧支持搜索，以及经营实体、部门、外协单位筛选。
- 公司根组织不作为日常可操作列表项，人员不能直接归属公司根。
- 右侧包含：概览、人员、职责权限、项目、变更记录。
- 普通部门不显示项目和野外项目报送人员入口。
- 当前负责人单独显示；组织管理员可多人；项目管理员在具体项目中维护。
- 候选人员只显示符合资格的 active 正式员工。
- 尚未开通账号的人员可显示“已授权，账号待激活”，但不能行使权限。

## 项目与成员

- 使用与组织页一致的“左侧目录＋右侧工作台”。
- 右侧包含：项目概览、项目成员、项目管理员、加入申请、培训关联、变更记录。
- 培训关联只显示摘要并跳转培训模块，不复制培训业务页面。
- 项目月报仍由野外项目报送模块维护。

## 审核中心

- 统一承接身份绑定、手机号或微信换绑、部门调动、新注册、项目关系和账号合并/异常申请。
- 默认显示“待我处理”，另设“我已处理”和“全部记录”。
- 左侧菜单显示服务端返回的待办数量。
- 审核详情在同一工作台右侧完成，避免多层弹窗。
- 部门管理员只能看到并处理服务端授权组织范围内的申请；公司管理员保留全局兜底能力。

## 数据工具

- 人员 Excel 导入与增量补全。
- 人员照片 ZIP 导入。
- 批量调整主部门。
- 导入记录与失败明细。
- 敏感资料导出。
- 导入模板下载。
- 人员导入继续执行“上传、预检查、组织匹配、冲突处理、确认写入、结果”流程；已有人员只补全明确选定的空缺字段。

## 删除与停用

- 批量停用用于离职、退休或退出当前管理范围，保留全部历史记录。
- “清理误建档案”仅公司管理员可用；服务端逐人检查，仅完全没有业务引用的空档案可以物理删除。
- 批量操作先返回可处理、不可处理及原因，再二次确认；不提供强制删除。

## 非目标

- 不修改 Prisma 数据模型或新增 migration，除非实施时发现现有结构无法表达已确认状态。
- 不改变既有角色规则、组织边界、账号生命周期和审计要求。
- 不重新实现人员导入、账号重置、微信绑定或项目成员业务。
- 不修改培训教育、资质证照、野外项目报送和应收账款模块的业务逻辑。
- 不引入新的前端状态管理或 UI 依赖。

## 验收标准

- 同一人员不再出现在两张职责重叠的总表中。
- 搜索人员后可从详情完成档案、账号和角色相关操作。
- 组织和项目均可在不分页、不横向滚动的情况下定位和管理。
- 审核、导入、敏感导出与日常人员浏览相互分离。
- 服务端权限边界和现有审计行为不回退。
- Admin typecheck 和 production build 通过，现有人员/账号/角色策略检查通过。
