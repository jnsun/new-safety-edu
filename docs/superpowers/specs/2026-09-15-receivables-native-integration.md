# 应收账款管理原生迁移规格

日期：2026-09-15

状态：`FINAL PASS / APPROVED FOR MERGE`（2026-09-16 在 Node.js 22.23.2、PostgreSQL 16.15、三个全新隔离数据库上完成第二次完整连续 FINAL；生产切换仍须逐项执行切换手册）

## 1. 目标

把旧的企业应收账款台账作为主系统 Web 管理后台第九个业务模块原生实现。模块入口名称为“应收账款管理”，描述为“合同应收、开票回款与催收台账”，路由为 `/receivables`。

模块使用主系统 React、Ant Design、Fastify、Prisma/PostgreSQL、账号会话、事务审计、通知和私有文件能力。生产环境不再加载 Supabase SDK、发布密钥或访问 Supabase，也不做双写。

## 2. 不做事项

- 不迁移旧 Supabase 账号、权限、偏好、导入批次、测试台账或预览数据。
- 不把财务归属部门合并到平台组织主档。
- 不把财务合同关联到平台项目主档。
- 首版不进入微信小程序。
- 不保留独立登录页、iframe 或浏览器直连数据库。
- 不追求旧静态页面像素级复刻。
- 不增加通用工作流引擎、通用授权框架或通用后台任务框架。

## 3. 领域规则

- 一行台账等于一个合同。
- 合同编号必填，去除首尾空格后全公司唯一，由数据库约束保证。
- 财务归属部门是模块独立主档，允许保留改名前和历史经营实体名称；停用后不能承接新台账，但继续承载历史。
- 财务归属部门与债权单位正交；债权单位为物化院、六勘院、测绘院、禹地公司等财务字典值。
- 台账不关联平台项目主档。
- 非工作量结算时，合同金额自动带入决算金额；财务管理员仍可更正。
- 决算金额为空时，账外应收和应收余额为空且不参与合计，账内应收继续计算。
- 开票金额等于有效开票明细合计，到账金额等于有效回款明细合计，两者不单独手工维护。
- 只有历史 Excel 汇总额、没有逐笔明细时，生成来源为“期初导入”的明细。
- 账内应收 = 开票金额 - 到账金额。
- 账外应收 = 决算金额 - 开票金额。
- 应收余额 = 决算金额 - 到账金额 - 核销金额。
- 真实回款可以形成负余额，负余额显示为超收并进入待核对事项。
- 新增或调高核销金额不得超过当时未收余额；后续回款形成负余额时标记核销待调减。
- 债权状态人工维护，不自动判断逾期。
- 最新挂账时间取最近一笔有效开票日期；没有明细时可保留期初导入日期。
- 默认查看未结台账，已结清和已作废记录可明确切换查看。
- 核销是可调整金额，不是结案状态。

## 4. 启用与权限

### 4.1 财务资产部绑定

- 主系统配置保存一个稳定的 `Organization.id`，目标必须为 `department` 类型。
- 该组织当前唯一、有效的 `org_leader` 自动成为应收账款负责人。
- 首次绑定由公司管理员在组织管理入口完成；后续换绑要求原因、二次确认和事务审计。
- 未绑定、无当前负责人或初始财务配置未确认时，模块处于待配置状态，不能访问财务数据页。
- 公司管理员仅能执行紧急绑定、任命或替换负责人，默认不能读取或修改财务数据。

### 4.2 模块角色

- 应收账款负责人：全部业务权限和授权管理权，由财务资产部当前负责人派生，不单独存储。
- 财务管理员：由负责人任命，可管理全部台账、金额、明细、配置、导入导出，但不能任命负责人。
- 财务归属部门报账员：可关联一个或多个财务归属部门，默认只能维护催收字段和附件。
- 财务只读人员：只能读取被授权财务归属部门。
- 查看全部是独立能力，不能通过客户端选择部门扩大。
- 报账员新增台账和报账员/只读人员导出分别为独立加开能力。
- 导入和批次回滚仅负责人或财务管理员可执行。
- 财务授权撤销后下一次财务请求立即拒绝，但不终止用户的其他平台会话。
- 只有 active 账号且关联 active 人员时才能使用财务权限。

### 4.3 报账员字段边界

获准新增的报账员可以填写授权范围内的财务归属部门、合同编号、项目名称、客户名称、客户属性、债权单位、工作性质、板块、项目状态、决算方式、催收字段和附件。

报账员不能填写或修改决算金额、开票、回款、核销、财务授权或范围。正式提交后的合同编号仅负责人或财务管理员可更正。所有限制由服务端执行，前端隐藏只用于改善体验。

## 5. 生命周期和审计

- 正式台账不物理删除，错误记录填写原因后作废并退出正常统计。
- 开票和回款明细不物理删除，错误明细填写原因后作废或冲销。
- 导入批次不物理删除，整批回滚保留原批次、逐行影响和更正历史。
- 财务附件不物理删除，使用作废状态保留原文件和元数据。
- 财务归属部门和在用字典不物理删除；改名默认停用旧值并新增新值。
- 历史台账整体归属迁移和字典值批量迁移仅负责人可执行，提交前显示影响数量并二次确认。
- 所有更新带版本号；版本不一致返回 409，客户端展示最新值并要求重新确认，不自动合并金额、归属或作废状态。
- 台账、金额、明细、作废、迁移、授权、导入、导出、附件上传下载和紧急恢复使用事务型关键审计。
- 审计保存操作者、时间、原因、对象、结果、权限范围和变更前后摘要；普通列表浏览不逐次记录。

## 6. 导入、导出和附件

### 6.1 Excel 导入

- 服务端保存上传文件及 SHA-256，并负责解析和校验，客户端不提交可信业务载荷。
- 先完整校验并返回预览，再由用户对重复合同逐行选择跳过或更新。
- 存在阻断错误时整批不写入。
- 更新只覆盖预览中明确列出的台账字段，不覆盖开票、回款、附件或审计历史。
- 应用在一个数据库事务中全部成功或全部失败。
- 批次回滚在目标记录发生后续修改时返回冲突，不静默覆盖后续事实。

### 6.2 Excel 导出

- 负责人和财务管理员可导出全部。
- 报账员和只读人员只有单独导出能力时才能导出，并且不扩大当前可见部门范围。
- 导出保存不可变范围和筛选快照，使用后台任务生成 XLSX。
- 下载使用短时、一次性令牌；请求、完成、领取和过期清理均审计。

### 6.3 附件

- 使用主系统 `PrivateFile` 和本地私有存储。
- 单文件最大 10MB，只允许 PDF、PNG、JPG、WebP 和 XLSX。
- 保存原文件名、MIME、大小和 SHA-256；读取时按当前台账权限重新鉴权并记录审计。
- 报账员可上传并作废本人上传的附件；负责人和财务管理员可作废任意财务附件。

## 7. 页面范围

- 九宫格入口按服务端返回的模块能力显示；无财务权限的 active 用户不可见。
- 公司管理员只在缺少初始绑定时看到“待配置”，恢复入口位于组织管理而非财务数据页。
- 财务模块侧栏包含看板、台账、导入批次、财务授权、财务归属部门和业务字典；菜单按能力隐藏。
- 台账保留宽表、服务端筛选排序分页、列显示顺序偏好、冻结列、详情、开票、回款和附件能力。
- 看板聚合只使用当前服务端可见范围，显示未结、决算未定、超收、核销待调减及其他已确认指标。
- “用户管理”替换为“财务授权管理”，不创建独立账号。
