# 人员与组织管理模块界面优化设计

## 目标

在不改变人员、账号、组织、项目、角色和审核业务规则的前提下，统一人员与组织管理模块的界面结构，解决组织目录较长时选中下方部门后仍需滚回页面顶部查看人员的问题，并降低人员档案、项目成员、审核中心和数据工具之间的操作差异。

本轮只调整 Admin 前端的信息层级、布局、滚动行为和状态保持。复用现有 API、服务端权限和数据模型，不修改培训教育、资质证照、野外项目报送、应收账款和微信小程序业务。

## 使用场景与设计原则

该模块属于高频操作型后台界面。主要使用者需要在 20–30 个经营实体、部门和外协单位之间快速切换，并查看少则数人、多则数十人的人员与权限信息。

设计原则：

1. 左侧用于定位对象，右侧用于查看和处理当前对象。
2. 目录与详情分别滚动，不让浏览器页面滚动破坏当前上下文。
3. 人数是辅助定位信息，不能决定组织是否显示。
4. 人少时只显示真实行数，不填充空白行、不增加无意义分页。
5. 同类页面使用同一套搜索、筛选、选中、详情和返回逻辑。
6. 服务端权限仍是唯一授权依据，前端布局调整不得扩大数据范围。

## 模块信息架构

保留现有入口：

1. 人员档案
2. 组织与职责
3. 项目与成员
4. 审核中心
5. 数据工具
6. 账号异常处理，仅公司管理员可见

不恢复独立的“账号与权限”总表。账号、微信绑定和角色授权继续归入人员详情或相应组织、项目工作台。

## 组织与职责

### 桌面布局

采用已确认的固定双栏工作台：

- 左栏宽度约 280–300px，包含固定搜索区、类型筛选和独立滚动目录。
- 右栏占据剩余宽度，包含固定对象标题、操作区、页签和独立滚动详情。
- 工作台高度随浏览器可视区计算，左右两栏都必须设置正确的 `min-height: 0` 和内部 `overflow`，避免滚动回落到整个页面。
- 选择左侧任意组织后，右栏滚动位置重置到顶部并立即显示该组织内容。
- 当前组织写入 URL 查询参数 `organizationId`，刷新页面和从人员详情返回后仍保留当前选择。

### 组织目录

- 排除公司根组织。
- 按“经营实体、部门、外协单位”分组。
- 分组显示数量并支持折叠；默认展开经营实体和部门，外协单位可折叠。
- 搜索匹配组织名称；类型筛选提供“全部、经营实体、部门、外协单位”。
- 每行保持紧凑高度，显示组织名称和当前人数。
- 长名称省略显示，悬停或键盘聚焦时提供完整名称。
- 当前项具有明确的选中状态和可见焦点。
- 20–30 个组织不引入虚拟列表、复杂树形组件、收藏或最近使用机制。

### 组织详情

右侧页签为：

1. 概览
2. 人员
3. 职责权限
4. 项目，仅经营实体显示
5. 变更记录

人员页签默认展示当前组织真实人员行数，不分页。表格至少显示姓名、人员类型、手机号、账号状态、本组织职责和人员状态。姓名进入独立人员详情。

标题区显示组织名称、类型、当前人数和账号摘要。编辑组织、管理职责和删除等动作集中在标题区；危险操作仍需二次确认。

普通部门不显示项目和野外项目报送人员入口。外协单位只显示与外协人员相关的必要信息，不出现内部管理授权入口。

## 人员档案与人员详情

### 人员列表

- 默认平铺列表，继续支持“按部门分组”视图。
- 筛选栏在列表滚动时保持可见。
- 支持姓名、手机号、用户名或工号搜索，以及组织、人员状态、账号状态和管理职责筛选。
- 主表仅展示识别和判断所需字段，不在每行堆放账号、微信、角色等全部操作按钮。
- 姓名是进入人员详情的主要入口。
- 批量操作只在勾选人员后显示；未选择时不占据页面空间。
- 返回列表时恢复搜索条件、筛选条件、页码、视图模式和滚动位置。

### 人员详情

保留独立路由和以下页签：

1. 基本档案
2. 账号与微信
3. 组织与职责
4. 项目关系
5. 证照
6. 培训记录
7. 申请与变更
8. 操作记录

左侧或顶部提供简洁身份摘要，正文只展示当前页签内容。停用人员、停用账号、解除微信、账号合并和误建档案清理继续集中在“谨慎操作”区域。

## 项目与成员

沿用组织页的双栏工作台：

- 左侧按状态筛选和搜索项目，并显示成员数与责任经营实体。
- 右侧页签为项目概览、项目成员、项目管理员、加入申请、培训关联和变更记录。
- 选择项目后右侧回到顶部，刷新和返回时保留当前项目。
- 项目成员、管理员和申请在右侧同页处理，避免多层弹窗。
- 培训关联只展示摘要并跳转培训模块，不复制培训业务页面。

## 审核中心

采用“左侧待办队列＋右侧审核详情”：

- 左侧提供待我处理、我已处理和全部记录。
- 可按申请类型、组织、项目和状态筛选。
- 右侧显示申请摘要、验证状态、匹配候选、冲突提示、审核意见和可执行动作。
- 审核动作尽量在详情区完成；只有不可逆或高风险确认使用弹窗。
- 部门管理员只能看到服务端返回的本组织申请，公司管理员保留全局兜底能力。

## 数据工具与账号异常处理

数据工具采用纵向任务清单，不使用同尺寸卡片网格。按以下顺序排列：

1. 人员 Excel 导入与增量补全
2. 人员照片 ZIP 导入
3. 批量调整主部门
4. 导入记录与失败明细
5. 敏感资料导出
6. 导入模板下载

每项显示用途、风险提示、最近结果和唯一主操作。现有预检查、确认写入、冲突处理和审计规则不变。

账号异常处理仍仅公司管理员可见，用于待激活、已停用、已合并、重复绑定和资料异常账号，不恢复正常账号总表。

## 响应式与无障碍

- 宽屏使用固定双栏。
- 中等宽度保持双栏，但收紧目录宽度并允许表格隐藏次要列。
- 小于约 900px 时，组织或项目目录改为顶部可搜索切换器或受控折叠区，详情在其下方显示；不在小屏强行保留狭窄双栏。
- 键盘焦点顺序与视觉顺序一致；目录项、页签和操作按钮均有明确焦点状态。
- 列表、详情和审核必须包含加载、空数据、错误、无权限和重试状态。
- 不增加装饰动画；仅在目录选择、页签切换和折叠时使用短时状态过渡。

## 前端边界

优先抽取少量共享结构，避免继续扩大 `App.tsx`：

- 一个通用双栏工作台外壳，负责高度、目录、详情和响应式行为。
- 组织、项目和审核各自维护数据查询、权限和业务操作。
- 人员筛选和组织成员筛选复用现有纯函数。

不引入新的状态管理库、表格库、虚拟滚动库或设计依赖。现有 Ant Design、React Router 和 TanStack Query 足以完成本轮优化。

## 数据与权限

- 不新增 Prisma migration。
- 不修改数据库结构。
- 不新增平行业务模型。
- 不改变任何角色授权矩阵、人员范围、项目范围或敏感字段策略。
- 页面上显示的数据必须来自现有服务端鉴权后的 API 响应。
- 前端筛选、隐藏和禁用仅用于交互提示，不能替代服务端鉴权。

## 验收标准

1. 在包含至少 20 个组织的目录中选择底部组织，不滚动整个页面即可立即看到该组织详情。
2. 左侧搜索和类型筛选在目录滚动时持续可见。
3. 右侧组织标题和页签在详情滚动时持续可见。
4. 只有数名人员的组织只显示真实人员行数，不分页、不填充空白行。
5. 组织切换后详情滚动到顶部；刷新和返回后选择状态可恢复。
6. 人员列表返回状态可恢复，姓名可进入独立详情。
7. 项目与审核中心使用与组织页一致的定位和详情逻辑。
8. 小屏不出现不可用的狭窄双栏或页面级横向滚动。
9. 加载、空数据、错误和无权限状态具有明确说明和恢复动作。
10. Admin 类型检查、production build、现有人员/账号/角色策略检查通过。
11. 不改变培训教育及其他业务模块的功能和路由。
