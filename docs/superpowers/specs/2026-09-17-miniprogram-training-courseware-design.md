# 小程序培训学习、互动课件与日常安全挑战设计

日期：2026-09-17
状态：已完成业务确认，待用户审阅后进入实施计划

## 1. 目标与受众

本设计面向公司正式员工、外协人员和临时个人在微信小程序中的安全培训学习。员工既可能利用 5—10 分钟工作间隙学习，也可能在安排好的 15—30 分钟时段连续完成课程。

目标不是把制度文件搬到手机，而是让员工始终知道“现在该做什么”，通过短单元、真实场景、即时反馈和可恢复进度完成学习，同时保留现有培训任务、考试、补学、签字和培训档案的权威业务闭环。

## 2. 已确认的体验方向

### 2.1 待办首页

- 使用“任务指挥台”布局，第一屏突出当前最应完成的一项。
- 任务按逾期、临近截止、普通任务排序。
- 每项显示培训名称、类型、截止时间、状态、进度和唯一下一步动作。
- 日常安全挑战位于正式待办之后，不能压过必须完成的培训任务。

### 2.2 培训任务详情

- 顶部显示培训名称、范围、截止时间和整体进度。
- 使用醒目的“当前下一步”操作区。
- 以“学习 → 考试 → 签字 → 完成”显示阶段进度。
- 所有必学课件均可查看，不逐级解锁；只有全部完成后才允许考试。
- 补学、锁定、待签字和待项目确认分别使用明确的状态说明，不显示无效操作按钮。

### 2.3 考试

- 采用“单题沉浸”模式，一屏只显示一道题。
- 顶部固定显示剩余时间、已答题数和总进度。
- 提供上一题、下一题和交卷前检查。
- 每次选择后自动保存并显示保存结果。
- 退出后恢复原 attempt、答案、当前位置和剩余时间。
- 正确答案与评分规则在最终交卷前不得下发客户端。

### 2.4 签字与培训记录

- 签字前展示培训记录摘要，Canvas 提供清空、预览和正式提交。
- 正式签字提交后本人不能覆盖。
- 培训记录优先显示名称、完成时间、最终成绩、是否通过和签字状态。
- 详情按学习内容、考试结果、签字和项目确认分区。

## 3. 互动课件体系

### 3.1 默认结构

一门典型的 15—25 分钟课程由多个 5—8 分钟单元组成：

1. 情境开场：使用真实工作问题说明为什么要学。
2. 核心知识卡：一屏一个重点，避免长篇连续文字。
3. 正误对比或操作步骤：明确应该做什么、不应该做什么。
4. 事故案例推演：员工选择处理方式后查看后果和制度依据。
5. 轻量互动：找隐患、步骤排序等。
6. 三点总结和随堂检查：检查理解，不计入正式考试成绩。

员工可连续完成全部单元，也可以退出后从原位置继续。页面显示预计时长、已完成单元和预计剩余内容。

### 3.2 内容形态

- **A 互动微课**作为默认形态：短单元、知识卡、正误对比和随堂判断。
- **B 情境故事**用于事故案例、风险辨识和应急处置：选择处理方式后展示结果及依据。
- **C 轻量小游戏**少量使用：找隐患、步骤排序等；不在正式课程中产生排行榜积分。
- 复杂情境分支和小游戏继续使用受控的单文件 HTML。
- 不自动播放声音，不强制观看装饰动画，不建设视频学习体系。

### 3.3 学习完成

- 结构化课件由小程序原生渲染。
- 客户端记录阅读位置，但课件打开、到达末尾和完成学习仍由服务端记录并校验。
- 随堂题用于解释和复习，不替代正式考试，不影响培训是否通过。
- HTML 课件继续通过短时授权 viewer 打开，不公开文件目录。

## 4. 可视化课件编辑器

### 4.1 编辑模式

采用适配手机的纵向内容块编辑器，不建设 PowerPoint 式自由画布。第一版内容块包括：

- 课程封面、摘要、学习目标和预计时长；
- 单元标题；
- 图文知识卡；
- 重点提示与警告；
- “应该 / 不应该”正误对比；
- 操作步骤；
- 图片与说明；
- 单选、多选、判断随堂题；
- 一层情境选择、选择后果与制度依据；
- 三点总结；
- HTML 互动内容入口。

支持添加、复制、删除、上下移动、草稿保存、手机预览和发布新版本。已发布版本不得原地修改；编辑已发布课件时创建新草稿版本。

### 4.2 批量导入、导出与系统模板

支持三种互补格式：

- **XLSX**：用于日常批量制作和修改多门课程。
- **JSON**：用于无损导入导出全部结构化内容和配置。
- **ZIP 课件包**：包含 JSON 或 XLSX 清单以及配套 `assets/` 素材。

后台必须提供下载入口：

- 空白 XLSX 系统模板；
- 带匿名示例内容的 XLSX 模板；
- JSON 示例文件；
- JSON Schema；
- 字段说明和当前模板版本。

XLSX 使用以下工作表：

1. `课程`：课程编码、标题、摘要、范围、预计时长。
2. `单元`：课程编码、单元编码、标题、顺序、预计时长。
3. `内容块`：单元编码、块类型、标题、正文、素材文件名、顺序。
4. `随堂题`：单元编码、题型、题干、选项、答案、解析。
5. `情境选择`：场景、选项、选择后果、制度依据。
6. `导入说明`：字段解释、允许值和匿名示例。

一个 XLSX 可以包含多门课程。课程编码和单元编码是稳定匹配键，不根据中文标题模糊匹配。

### 4.3 导入流程与安全

流程固定为：

上传 → 服务端解析 → 预检查 → 显示新增、更新、冲突和错误 → 人工确认 → 写入草稿 → 手机预览 → 发布新版本。

- 每项错误显示文件、工作表、行号、字段和原因，不得静默跳过。
- 已发布版本永不覆盖；重新导入生成新草稿版本。
- 素材通过 ZIP 内的精确相对文件名关联，不进行模糊匹配。
- 拒绝路径穿越、可执行文件、宏工作簿和超限素材。
- JSON 只作为数据解析，不执行其中的脚本。
- 不支持直接导入 Word、PDF 或 PPT；这些格式不作为结构化课件来源。
- 复杂 HTML 仍通过现有私有文件上传流程单独管理。

## 5. 日常安全挑战

### 5.1 业务边界

日常安全挑战是独立的自愿学习入口。积分只来自日常挑战，不来自正式培训任务、正式考试、补学、签字或项目确认，也不能替代任何培训事实。

### 5.2 题目来源与答题规则

- 复用现有题库，题目增加“可用于日常安全挑战”配置。
- 可配置知识分类、难度和适用组织范围。
- 每人每天随机 5 题。
- 每题首次作答正确得 2 分，答错不扣分并立即显示解析。
- 答错后允许重新练习，但重复作答不再得分。
- 每日普通答题最多获得 10 分。
- 找隐患、步骤排序等小游戏首次完成可获得固定积分；同一内容同一月份重复完成不再得分。
- 客户端只提交答案或完成证据，积分由服务端计算。

## 6. 积分与排行榜

### 6.1 个人榜

- 每个自然月独立排名，历史月份永久可查。
- 展示当月前 20 名的姓名、部门、积分和排名变化。
- 当前用户不在前 20 名时，仍显示本人及前后各两名。
- 同分时按更早达到该积分的时间排序。
- 不显示照片、手机号、身份证或培训考试成绩。
- 个人保留累计总积分，但累计积分不改变月榜排序。

### 6.2 部门榜

- 部门分数为本月有效积分总和除以 active 人员数。
- 同时显示积分、参与人数、部门总人数和参与率。
- 少于 3 人的部门标记为“小样本”，展示成绩但不参与奖励排名。
- 外协单位不参加内部部门榜。
- 积分按获得积分时的当前主部门记入，历史月榜在结算后保持不变。

### 6.3 管理与奖励边界

- 管理员可以作废异常积分，必须填写原因并写审计；不能直接随意给个人加分。
- 当前版本不建设奖励配置、积分商城、兑换、库存或发奖流程。
- 排名奖励由公司线下决定，系统只展示排名事实。

## 7. 数据模型方向

必须扩展现有主模型，不建立平行课件、人员、组织或题库体系：

- `CoursewareType` 增加结构化课件类型，原有 `rich_text` 和 `single_html` 保持可用。
- `CoursewareVersion` 保存带 schema 版本的结构化内容、预计时长和内容 hash。
- `LearningProgress` 保存可恢复的课件位置；完成字段继续由现有服务端流程维护。
- `Question` 增加日常挑战启用状态、分类、难度和适用配置。
- 新增每日挑战答题、答题项和不可变积分流水；同一来源通过业务唯一键防止重复计分。
- 积分流水保存获得积分时的组织快照。历史月份结算后保存部门人数和排名快照。
- 课件批量导入保存源文件 hash、模板版本、预检查结果和确认结果，防止重复确认写入。

具体字段、约束和索引在实施计划中以当前 Prisma schema 为准确定。

## 8. 权限与审计

- 沿用现有课件 scope、发布授权和服务端权限校验。
- 编辑、导入、确认导入、发布、生成新版本、挑战题启停和异常积分作废均写审计。
- 小程序只能读取本人任务、本人挑战、公开的公司内部排行榜和本人积分记录。
- 任何客户端隐藏按钮都不能替代 API 鉴权。
- 素材、HTML 和导入源文件使用私有存储，不进入公开静态目录。

## 9. 状态与错误处理

- 所有学习页面提供加载、空状态、网络失败、重新加载和保存失败提示。
- 自动保存失败时保留本地当前选择并明确提示重试，不伪装成已保存。
- 导入预览过期、模板版本不兼容、文件损坏和内容冲突均提供可执行的中文提示。
- 每日挑战题目不足时减少当日题量并显示真实数量，不重复发放同题积分。
- 排行榜无参与数据时显示说明，不伪造排名。

## 10. 交付顺序

1. 优化小程序待办、任务详情、学习、单题考试、签字和培训记录。
2. 增加结构化课件 schema、服务端接口和小程序原生渲染器。
3. 建设后台纵向内容块编辑器、手机预览和版本发布。
4. 实现 XLSX、JSON、ZIP 导入预览确认、导出和系统模板下载。
5. 实现日常安全挑战、积分流水和个人/部门月榜。
6. 使用匿名内容制作一门完整示例课程并完成最小主流程验证。

每批只执行受影响的类型检查、production build、Prisma migration 校验和必要 API 手工验证；不建立大型测试体系。

## 11. 明确不开发

- 积分商城、奖励兑换、库存和发奖流程；
- 积分影响培训完成、考试结果或准入结论；
- PowerPoint 式自由画布编辑器；
- 复杂动画制作引擎；
- 视频学习体系；
- Word、PDF、PPT 自动转结构化课件；
- 客户端提交或修改积分；
- 第二套人员、组织、题库或培训记录模型。
