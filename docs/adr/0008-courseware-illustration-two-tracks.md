# 课件配图分场景写实与器材图解两路

- 状态：已接受
- 日期：2026-09-23

## 背景

安全培训配图同时承担两个互相拉扯的要求：**可信**和**准确**。

**可信**要求画面是真实场景。同事看到自己每天走过的那条走廊、那扇防火门、那个灭火器点位，注意力才会从"又一份培训"里抬起来。参考设计正是用了写实照片来做这件事。

**准确**在器材类画面上是硬约束，而且比可信更硬。生成模型画手提式灭火器时，压力表指针位置、保险销是否拔出、瓶身标识色块、软管朝向都可能出错——而"灭火器长什么样、怎么取用"**正是这类课程要教的内容**。一张画错的器材图会让学员记住错误的样子，且一定会在安全专业内容审核环节被打回。

此外，现有内容制作规范要求**不把中文烘焙进图片**：图片上写死的文字改一次就要重出一张图；小程序按宽度等比显示、不做裁切（`mode="widthFix"`），图上小字缩放后在手机上难以辨认；而需要逐字准确的中文（条款、警示语、步骤）本应由页面文字渲染。

最后还有一个现有实现的约束：图片只能绑定在 `knowledge` 块上、一块最多一张，且渲染在正文下方、通栏出血贴卡片底边并带底部圆角。

## 决策

课件的配图按两类分工，不使用单一风格：

- **场景与环境类**（走廊、办公空间、疏散通道、室外照度）走**写实风格**，优先使用本单位实拍；暂未取得实拍时用生成图占位。写实图内**不出现人物、不出现任何文字**。
- **器材、装备、操作细节类**（灭火器、消火栓、防火门构件、插排、配电箱）走**扁平图解**，严格扁平、无高光无 3D、无文字无人物；已有素材（`FIRE-IMG-001` 手提式灭火器、`FIRE-IMG-002` 门前堆物遮挡出口）即为该路线。

两类图都必须：主体距画面四边 ≥8% 安全区；重点不放在画面最底部（会被底部圆角吃掉）；浅色、干净、自然光或低饱和配色，与小程序蓝白配色不冲突；单文件 ≤500 KiB（建议），1600×900。

系统层面：**不支持 SVG**，只接受 JPG / PNG / WebP，扁平图解须先栅格化为 PNG。

## 考虑过的替代方案

- **全部扁平图解**：零器材画错风险、风格统一、已有两张底图。放弃原因是扁平图读起来像"图解说明"而不是"我们的现场"，对唤起风险意识的力度明显弱于实拍。
- **全部写实**：质感最好。放弃原因就是上面的准确性风险——这门课要教的器材本身不能画错，且写实图单张产出成本高得多。
- **把版面或标语画进图片**：可以直接复现参考设计里"图上有中文标语"的效果。明确否决：违反"需要逐字准确的中文由页面渲染"的既有规范，改文案要重出图，缩放后不可读，并且会用图片绕过 ADR-0007 对渲染层不动的约束。

## 后果

- 同一门课内存在两种视觉语言，需要用**构图与色调**统一（浅色底、主体居中、留白一致），而不是靠笔触风格统一。这是可接受的，因为两类图承担的教学功能本来就不同。
- 图的任务分配成为每门课的固定动作：先问"这张图是让人认出环境，还是让人看清器材"，再决定走哪条线。
- 生成图是**占位**，不是终态。取得实拍后按同一 `blockKey + path` 绑定关系替换文件、重新打包，内容块不需要改动。
- 实拍需满足：不拍人、不拍涉密区域、拍摄前确认可对外使用。
- 所有配图在发布前必须经人工复核，重点核对消防器材状态与作业动作；此项与安全专业内容审核并列为发布前置条件。
