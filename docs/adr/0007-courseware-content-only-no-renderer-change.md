# 首批专题课件只做内容，不改小程序渲染层

- 状态：已接受
- 日期：2026-09-23

## 背景

首批专题课件有一份参考设计，提出了比现有实现丰富得多的课件版面：进度条与"第 X / Y 项"的重新排版、标题下的强调线、应做/不应做的双栏卡片配圆形对勾与叉、"关键提醒"警示框、选项的字母圆标与选中打勾、随堂题答对后的学分徽章、"学习后行动提示"的图标卡、页脚标语。

现有实现（`apps/miniprogram/components/courseware-blocks/`）与它的差距不在内容，而在渲染层：

- 图片只能在 `knowledge` 块上挂一张，且渲染在**正文下方**、通栏出血贴卡片底边。
- `do_dont` 固定渲染为上下两栏加数字序号，没有图标位。
- 没有通用提示框字段；`body` 是纯文本，不支持加粗或列表。
- 随堂题在平台里**明确不计分**，积分只归"每日安全挑战"。
- 页脚、面包屑、标语胶囊属于页面级模板，内容层不可控。

要做出参考设计的版面，需要同时改小程序组件、结构化课件 JSON schema，并连带改导入器、编辑器与后台预检——之后还要重新提审小程序。

与此同时，首批两门专题课的当前目标是**尽快完成一次真实的端到端试点**：ZIP 导入 → 发布 → 下发 → 小程序学习 → 签字 → 记录。这一步已经因为"不能按人员零散下发"和"真机未验证"处于阻塞状态，再叠加一次渲染层改造会把试点进一步推后。

## 决策

首批《消防专题培训》《秋季地质勘查安全专题培训》**只做内容**：只使用现有的六类内容块（`knowledge`、`do_dont`、`steps`、`checkpoint`、`scenario`、`summary`）与现有字段，不改小程序代码、不改结构化课件 schema、不改导入器。

参考设计中依赖渲染层或新字段的元素一律不实现。需要独立呈现的提示，改写为单独的内容块；需要强调的条目，写进 `do_dont` 或 `steps` 的条目文字本身。

## 考虑过的替代方案

- **改渲染层**：视觉上限最高，效果可复用于全部后续课件。放弃原因是它把"改组件 + 改 schema + 改导入器 + 重新提审"四件事绑在了一次试点上，而试点当前的价值在于验证链路而不是验证视觉。
- **改用 `single_html` 单文件课件**：版面无限制，但平台不回收 HTML 内部的滚动位置、交互答案和完成事件，学习进度与"已到达末尾"的服务端证据会失效；且现有 CSP 禁止外部资源，业务域名与真机尚未验证。培训合规依赖的正是这些证据，因此不采用。

## 后果

- 课件的视觉上限由现有组件决定，不会长得和参考设计一样。这是**已知且已接受**的取舍，不是缺陷。
- 导入包可以立即生产，不需要等待任何代码改动或提审。
- 学分、图标、双栏、提示框、页脚这些元素**不要写进内容稿**，也不要作为缺陷登记——它们在当前层级下不存在。
- 如果试点完成后确认视觉是硬需求，需要**单独立项**：改 `courseware-blocks` 组件 + 扩展 `packages/contracts/src/courseware.ts` 的块定义 + 同步导入器与后台编辑器 + 重新提审。该项不应混入内容制作。
- 内容制作方不得通过"把版面画进图片"来绕过本决策（见 ADR-0008 对图片内文字的约束）。
