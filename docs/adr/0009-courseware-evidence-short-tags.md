# 内容依据在课件内条目短挂，完整对照表随内容稿归档

- 状态：已接受
- 日期：2026-09-23

## 背景

培训内容要求逐条可溯源：每条做法都应能指出出自哪份制度、哪一条。这既是安全专业审核的依据，也是事后追溯的依据。内容制作规范明确要求"没有依据的制度条款不得编造"，并在内容稿第 0 节设有"依据文件及版本"栏逐项填写。

但平台的结构化内容块**没有引用或注释字段**：

- `knowledge` 的 `body` 是 1–10000 字符纯文本，不支持加粗、脚注或结构化引用；
- `do_dont` 的 `dos` / `donts` 每个条目是 1–500 字符裸文本；
- `steps` 的每一步、`summary` 的每一点同样是裸文本；
- 六类块中只有一个字段天生用于承载出处：`scenario` 的 `basis`（「判断依据」，1–3000 字符）。

于是"这一条出自《XX 管理办法》第 12 条"这句话只有两种落法，各有代价：

- **写进条目正文**：条目从一行变两行。`do_dont` 条目在手机上的可读上限约 24 字，挂上完整出处后接近 40 字，整块的节奏会散掉。
- **完全不写**：课件里出现无法对应到任何制度的做法，逐条溯源的要求落空。

## 决策

采用"**条目短挂 + 对照表另存**"：

1. 课件内只在**关键条目**后加**极短标注**，形如「（办法第12条）」，**不超过 6 个字符**。只对有明确条款支撑的条目标注；没有条款支撑的条目不加。
2. `scenario` 块的 `basis` 字段**优先使用**——它是唯一天生承载依据的字段，条款可以在此写全。
3. `checkpoint` 的答案解析可写完整依据句（上限 4000 字符，不挤占正文）。
4. **完整对应关系**（条目原文、对应文件名称与版本、条款号）写进 `内容稿.md` 的第 0 节制作信息，并另出一份**依据对照表**，随内容稿归档。
5. **依据对照表不进入课件。** 它服务于审核与追溯，员工看到的课件保持干净。
6. 短标注的长度计入条目字数上限（见《消防专题培训_样板课_制作规格》第 4 节：`do_dont` 条目含标注 ≤32 字）。

## 考虑过的替代方案

- **集中一个「依据一览」块**：正文最干净。放弃原因是条目与条款之间的对应关系要读者自己找，审核时也无法逐条核对，等于把溯源的负担转移给了使用者。
- **只在 Markdown 存档里留，课件完全不显示**：课件最干净。放弃原因是失去"这条有出处"的现场提示，学员无从判断哪些是硬性规定、哪些是建议。
- **依赖新字段**：给内容块增加 `reference` 或 `citation` 字段。这需要改 `packages/contracts/src/courseware.ts` 并同步导入器与后台编辑器，与 ADR-0007「首批不改渲染层与 schema」冲突，故不在本批次采用。

## 后果

- 课件正文保持可读，`do_dont` 条目不会因为挂依据而普遍换行。
- **课件本身不足以独立证明合规。** 发布与归档时必须**内容稿 + 依据对照表 + 导入包**三者一起留存；只保存 `courseware.json` 会丢失全部出处信息。审核记录与培训档案的归档流程需据此调整。
- 条款号短标注依赖内容稿中的完整记录才能还原，因此对照表一旦缺失，短标注不可反查。对照表是**必需交付物**，不是可选项。
- 未取得制度原文时，条款栏一律留空并标注「待核」，不得凭常识编造文件名称或条款号。
