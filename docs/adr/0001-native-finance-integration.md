# 应收账款管理原生并入主系统

应收账款管理替换 Web 管理后台九宫格第九项“事故事件管理”，使用主系统的 React、Ant Design、Fastify API、PostgreSQL、统一账号与会话、服务端权限和私有文件能力，不保留浏览器直连 Supabase、独立登录或 iframe，首版不进入微信小程序。正式入口为 `/receivables`，卡片描述为“合同应收、开票回款与催收台账”。迁移保留旧模块的完整业务流程和宽表能力，但不要求像素级复刻。现阶段没有正式数据和正式附件需要迁移，因此新模块以空库上线；只迁入经负责人复核的财务归属部门和业务字典初始配置，不导入旧账号、权限、偏好、批次、测试或预览数据。带独立 `.git` 的旧 Supabase 应用只作为本地只读迁移参考，不作为子模块或生产构建输入；功能等价验收后，经明确确认再移除旧运行代码和嵌套仓库元数据。

## Consequences

模块只有在稳定绑定财务资产部、存在当前负责人且负责人确认初始配置后才启用。列表、筛选、排序、统计和导出由服务端执行，不设静默截断；容量验证基线为五万份合同及五十万条开票、回款明细，大型导出采用后台任务。验收后一次切换旧 `/ledger/`，生产不再访问 Supabase 且不做双写，但保留部署前备份和版本回退能力。
