# 项目、合同与财务应收采用共享项目、独立权限和单向财务权威

## Status

Accepted

## Context

项目与合同资料要求投标、主合同、补充合同、分包合同及项目过程形成连续台账，但现有平台已经拥有人员、账号、组织和项目主档，财务应收又已经按“一行一个合同”维护开票、回款和历史金额。资料同时存在“一项目一主合同”、投标阶段尚未签约，以及财务中“一份合同可能代表多个项目”的口径冲突。旧实施规格还提出在新模块保存收款节点和直接费用，这会与财务权威重叠。

## Decision

复用统一 `Project`，不建立平行项目库。项目可在投标阶段先建立，主合同为可选关联；一份主合同只属于一个项目，一个项目至多关联一份主合同，并由数据库唯一约束保证。财务应收中“一行可能代表多个项目”只是既有财务台账口径，不改变主合同与项目的一对一业务规则，跨域关系仍须人工确认。投标结果、合同执行阶段与安全项目的启用、暂停、结束状态分别建模。投标中、未中标和放弃的项目不进入安全培训与野外月报清单；中标登记主合同后才可进入既有安全项目流程。

项目只保存一个责任经营实体，不再另设责任部门。历史资料中的部门、所、中心等显示名称必须先人工确认到统一 `Organization` 中的经营实体，界面显示名称但以稳定组织标识保存。

项目与合同访问采用单独授予人员的业务授权，并结合人员当前有效组织成员关系形成数据范围。安全角色、公司管理员身份和财务角色本身均不授予合同业务数据访问；公司管理员只可承担授权治理，不因此读取合同数据。

项目与合同域保存主合同约定额、补充合同增减额和分包合同约定额。实际开票、回款、核销、应收余额与历史仍由财务应收域唯一维护。本期不新增收款或成本台账，也不按合同编号自动双写。跨域关联必须由人员确认具体合同与财务台账的对应关系，确认后只读展示；合同编号只辅助核对，不自动建立关联。

分包付款和项目直接费用由后续财务成本或付款能力作为权威来源，项目与合同域只读汇总。若未来改由合同域记录，必须另行确定审批、冲销、税费和会计期间规则后修改本决策。

合同到期、质保和其他关键日期提醒可由项目与合同域后续实现，但本期不提供；实施前需单独确认提醒日期来源、提前天数、接收人员和关闭条件。

## Consequences

投标建项不再被必填主合同阻断；主合同不能在项目间共享，如需为另一项目登记合同，应使用其实际独立主合同。安全月报和培训继续使用原有项目生命周期，但必须排除尚未中标的合同项目。合同详情暂不显示实际回款和所谓利润；要展示现金流或盈利，需要另行确认付款、成本、税费和分摊的权威来源。

历史 Excel 只能先只读预检。字段映射必须保留来源工作表和行号，万元转换为元，按规范化合同编号查重，并生成来源相关幂等键；未获确认不得写入正式数据或提交源文件。当前只能提供带表头的版本，因此只验证结构，正式可导入记录数为 0。
