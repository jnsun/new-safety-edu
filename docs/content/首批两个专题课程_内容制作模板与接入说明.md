# 首批两个专题课程：内容制作模板与接入说明

> 适用范围：首批试点的《消防专题培训》和《秋季地质勘查安全专题培训》。
>
> 核查基线：本仓库当前实际代码；不以 Figma、历史方案或旧版 D00–D40 为实现依据。
>
> 本文只说明内容制作与现有系统接入，不授权修改业务代码、数据库、现有任务或生产配置。

## 1. 先给结论

唯一推荐路径是：**使用现有“结构化互动课件（`structured`）”，以两份人可读 Markdown 内容稿完成审校，再转换为一个包含 `courseware.json` 与 `assets/` 图片目录的 ZIP 导入包；培训类型使用“日常/年度培训（`routine`）”。**

选择这条路径的原因：

- 它是当前唯一同时具备原生图文、分单元逐项阅读、随堂题、情境选择、学习位置恢复和服务端完成记录的格式。
- ZIP 是现有后台可直接预检并导入“结构化数据 + 本地图片”的机器格式；Markdown 不是系统导入格式。
- `routine` 不要求正式考试、不触发项目现场确认，也不会被记为三级安全教育；管理员仍可主动开启正式考试，但首批轻量试点不建议开启。
- 当前所有普通线上培训在完成前都要本人签字，`routine` 也不例外；这不是内容文件可配置的字段。

当前有一个可能阻塞试点范围的缺口：**系统不能零散勾选试点人员，只能向完整组织或完整项目下发。** 如果现有某个完整组织/项目的在用人员恰好就是试点名单，可以直接试点；否则需要先补充“按人员下发”能力，不能通过伪造组织、改记录或关闭服务端校验绕过。

本文所说“已实现”是代码能力核查结论，不等于已经完成本轮真机端到端验收。ZIP 实包导入、发布、试点账号学习、断点恢复、签字和记录展示仍应在测试环境做一次完整验证。

### 2.1 课程内互动与正式考试必须分开理解

| 项目 | 课程内随堂互动 | 正式考试 |
| --- | --- | --- |
| 数据来源 | 结构化课件中的 `checkpoint`、`scenario` 块 | 独立题库、试卷和考试快照 |
| 是否计分 | 否 | 是 |
| 是否记录每题答案 | 否；只在当前页面内用于反馈 | 是；写入考试作答与考试次数 |
| 是否要求答对才能继续 | 否；随堂题提交任意答案后即可继续 | 是；按合格分与次数决定通过、补学或锁定 |
| 是否影响本次建议 | 建议每课 2–4 个，保持轻量 | `routine` 下建议关闭；若业务以后要求，再单独制作题库/试卷 |

### 2.2 当前完成链路

`打开课件（openedAt） → 逐项确认并保存位置 → 最后一项确认（reachedEndAt） → 点击“完成本次学习”（completedAt） → 如无正式考试则待签字 → 本人签字 → 培训任务 completed → 进入培训记录`

两门专题使用 `routine` 后，其记录类型是“日常/年度培训”，不会进入“三级安全教育”类型，也没有把专题完成事实折算成三级教育完成的代码路径。

## 3. 唯一推荐的交付物与接入路径

### 3.1 A 类：供人和 ChatGPT 编写、审校的文件

把以下文件交给 ChatGPT：

1. 本说明文档。
2. 如有公司现行制度、应急预案、作业规程或需要引用的权威资料，一并提供；没有依据的制度条款不得让 ChatGPT 编造。
3. 如有可复用且已确认版权/保密范围的图片原件，一并提供并说明可否裁切、改色。

要求 ChatGPT 返回：

1. `消防专题培训_内容稿.md`：按第 5 节模板完整填写，但不把占位说明保留在成稿中。
2. `秋季地质勘查安全专题培训_内容稿.md`：按第 6 节模板完整填写。
3. `courseware.json`：同时包含两门课，严格使用第 8 节机器字段；内容必须与两份 Markdown 一致。
4. `assets/`：仅放 `courseware.json` 实际引用的 JPG、PNG 或 WebP 图片，文件名与素材编号一致。
5. `素材核对表.md`：列出素材编号、文件名、对应 `blockKey`、替代文本、来源/生成说明，以及是否含需人工核对的安全细节。

Markdown 是审稿源，不是后台导入文件。它适合业务人员检查表达、顺序、依据和图片需求；系统不会直接读取它。

### 3.2 B 类：系统实际接收的格式

系统直接接收的是一个 ZIP：

```text
首批两个专题课程_导入包.zip
├─ courseware.json
└─ assets/
   ├─ fire/
   │  ├─ FIRE-IMG-001-opening.webp
   │  └─ FIRE-IMG-002-....jpg
   └─ geo-autumn/
      ├─ GEO-AUT-IMG-001-opening.webp
      └─ GEO-AUT-IMG-002-....png
```

ZIP 根目录必须且只能有一个清单文件：`courseware.json` 或 `courseware.xlsx`。本次固定使用 `courseware.json`，不要同时放 XLSX。除清单外的文件只能位于 `assets/` 下。

### 3.3 哪些内容直接导入，哪些要在后台填写

可随 ZIP 直接导入：

- 课程编码、课程标题、摘要、学习目标、预计总时长；
- 单元标题、单元预计时长、内容块顺序；
- 图文知识卡正文与其单张图片；
- 应做/不应做、步骤、随堂题、情境选择、总结；
- 图片与知识卡的绑定关系。

仍要管理员在后台完成：

- 选择导入适用范围并执行“预检 → 确认导入”；
- 审阅导入后生成的课件草稿并发布；
- 建立 `routine` 培训模板并按顺序选入两门已发布课件；
- 新建培训批次、关闭正式考试、填写培训说明/截止时间；
- 选择完整组织或完整项目、查看服务端覆盖预检并确认下发；
- 用真实试点账号在小程序完成学习、签字和记录核验。

需要 Codex 做的一次性接入工作：

- 对 ChatGPT 返回的两份 Markdown、`courseware.json` 和图片做一致性检查；
- 检查 JSON Schema、全局唯一 key、0 基答案索引、图片格式/文件头、路径和体积；
- 将 `courseware.json` 与 `assets/` 打成符合现有导入器规则的 ZIP；
- 在测试环境协助管理员处理预检错误，并核对导入后的移动端显示。该工作是内容转换与接入，不需要重构系统。

### 3.4 从内容到小程序学习的完整步骤

1. 内容负责人填写两份 Markdown 模板，并提供制度依据、审校意见和素材来源。
2. ChatGPT 产出两份内容稿、一个 `courseware.json`、图片目录和素材核对表。
3. 业务/安全负责人审核知识准确性；图片中设备状态、PPE、消防器材、地形和作业动作必须人工复核。
4. Codex 做格式校验并打成单个 ZIP。
5. 管理员进入 Web 管理端“培训教育 → 课件与模板 → 批量导入课件”，选择适用范围和 ZIP。
6. 先执行预检；确认两项均为“新增”或符合预期的“新版本”，且没有全局错误、冲突或无效项，再确认导入。
7. 导入结果是**草稿**。管理员打开课件编辑器检查顺序、图片、题目与预览，再逐门发布。
8. 管理员新建 `routine` 培训模板，按计划顺序选入已发布版本。若希望两门课是两个独立待办/独立记录，应分别建模板、分别下发；若放进同一模板，则两门课属于同一个培训任务，全部完成后才进入签字。
9. 管理员进入“培训安排 → 新建培训”：类型选“日常/年度培训”，正式考试保持关闭，选择范围，执行服务端预检并确认下发。
10. 试点人员在小程序“待办 → 任务详情 → 必学课件”学习；完成全部课件后本人签字；在“记录”查看结果。
11. 在宣布上线前完成至少一次测试环境实包与真机验证，尤其验证图片下载、断点恢复、随堂互动、末尾确认、签字和记录类型。

## 4. 内容结构与手机体验建议

以下是内容制作建议，不是代码硬限制：

- 每门课 3–4 个单元、8–14 个内容块、2–4 个互动块、8–15 分钟。
- 每个 `knowledge` 正文建议 80–220 个汉字；长内容拆成多个知识卡。
- 一张内容图片只服务一个明确知识点；不为按钮、标题、提示框和普通列表生图。
- 课程最后使用一个 `summary` 块；如需“学习后的行动提示”，可在总结前加一个 `steps` 或 `knowledge` 块。
- 需要逐字准确的中文、题目、答案、警示语和步骤由页面文字渲染，不烘焙进图片。
- 开篇主视觉可作为第一个 `knowledge` 块的图片，但它只在课件正文中出现，不会成为待办列表或任务详情封面。

## 1. 课程基本信息

- [系统必填] 课程名称：消防专题培训（title，1–180 字符）
- [系统必填] 课程摘要：<1–2000 字符；当前必填，但小程序学习接口暂未展示，主要用于后台编辑/导入>
- [制作说明] 适用人员：<供安排和审校；不是课件 JSON 字段，实际对象由培训下发范围决定>
- [系统必填] 学习目标（1–20 项；每项 1–500 字符）：
  1. <目标 1>
  2. <目标 2>
- [系统必填] 建议学习时长：<1–480 的整数，单位分钟>
- [当前不支持] 独立封面图片字段：无。开篇图使用 FIRE-IMG-001，并绑定到第一个 knowledge 块。
- [制作说明] 课程完成说明：依次确认所有内容块，到达末尾后点击“完成本次学习”；任务全部课件完成后仍须本人签字。此说明不是可配置规则。
- [制作说明] 建议规模：3–4 单元、8–14 块、2–4 个互动、8–15 分钟。

## 3. 随堂互动模板

### 随堂题 FIRE-Q001

- [系统必填] block key：FIRE-Q001
- [系统必填] type：checkpoint
- [系统必填] questionType：single_choice / multiple_choice / true_false
- [系统必填] 题干 prompt：<1–2000 字符>
- [系统必填] 选项 options（2–20 项；每项 1–500 字符）：
  1. <选项 A>
  2. <选项 B>
- [系统必填] 正确答案：<在内容稿中写选项字母；转换时写成从 0 开始的 correctIndexes，例如 A = [0]、A+C = [0,2]>
- [制作说明] 选对反馈：系统固定显示“回答正确”，不可自定义。
- [制作说明] 选错反馈：系统固定显示“回答不正确”，不可自定义。
- [系统必填] 统一解析 explanation：<1–4000 字符；无论答对答错都显示同一段>
- [制作说明] 是否允许重试：当前页面可重新选择并再次查看答案，但没有可配置开关，重试和答案不写入服务端。
- [制作说明] 是否影响课程完成：必须至少提交一次答案才可继续，但不要求答对，不计正式考试成绩。

### 情境选择 FIRE-S001

- [系统必填] block key：FIRE-S001

## 8. 结构化互动格式与最小示例

### 8.1 已支持的准确字段

文档顶层：

- `schemaVersion`：必须为整数 `1`。
- `title`：必填，1–180 字符。
- `summary`：必填，1–2000 字符；当前小程序学习接口不返回它。

- `estimatedMinutes`：必填整数，1–480；小程序课件头部显示。

- `key`：必填，1–120 字符，单元之间唯一。

## 9. 不推荐的格式及其真实限制

### 9.1 `rich_text`

- 后台只是一个“图文内容”文本框，API 保存一个非空字符串，小程序把字符串交给原生 `<rich-text>`。
- 没有 Markdown 解析器，因此 Markdown 标题、列表和图片语法不能视为可直接导入。
- 没有与正文配套的图片上传/资源重写字段、章节字段或课程内互动字段。
- 代码未提供专门的富文本安全清洗、外部图片域名管理或导入转换流程；外部图片能否在目标小程序环境加载属于待验证，不能作为首批可靠路径。

### 9.2 `single_html`

- 接受单个 `.html`/`.htm` 文件，MIME 必须为 `text/html`，硬限制 15 MiB。
- 通过五分钟有效的签名链接在小程序 `web-view` 中打开；是否满足目标微信环境的业务域名和真机要求仍待验证。
- 响应 CSP：默认禁止所有资源；图片仅允许 `data:`/`blob:`；样式和脚本只允许内联；`connect-src 'none'`；字体仅 `data:`；不允许 frame、object、表单提交、摄像头、麦克风、定位和支付。
- 允许内联 JavaScript，但不能依赖外部 JS/CSS、外部图片、API 请求或相对文件资源；单文件外没有资源包机制。
- HTML 内部滚动位置、交互答案和完成事件不会回传。用户返回课件页后，只能点击“本人确认已完成全部互动内容”，再完成学习。
- 现有代码没有定义 `postMessage`、JS Bridge、完成回调或进度消息格式，不得编造。

因此，本次不使用 HTML；它的交互自由度高，但真实进度和完成证据弱于结构化课件。

2. 点击“批量导入课件”。
3. 选择课件适用范围。公司范围只有公司管理员可选；组织/项目范围受当前管理员授权控制。
4. 上传 ZIP，点击“开始预检”。上传预检阶段不会写入课件。
5. 核对课程编码、标题、分类、逐项错误；有全局错误或没有可写入项时不能确认。
6. 点击“确认导入可写入项”。导入产生结构化课件草稿。
7. 返回课件列表，打开编辑器核对，再点击“发布”。发布需要相应范围的发布权限。

### 10.2 安排试点培训

1. 如果希望两门课分别产生任务与记录，分别为每门课建立一个 `routine` 模板；如果希望一次任务连续学完两门课，只建一个含两门课的模板。
2. 进入“培训安排 → 新建培训”。
3. 类型选择“日常/年度培训”；不要选“三级安全教育”。
4. 选择已发布课件/模板；正式考试保持关闭。
5. 在预览中确认显示“本次不要求正式考试”。签字仍按现有规则执行。
6. 范围只能选完整组织或完整项目。执行服务端预检，逐人核对“纳入人员/排除明细”。
7. 仅当预检名单与批准的试点名单完全一致时确认下发。

### 10.3 小程序预览与验收

1. 用纳入名单中的测试账号登录小程序；在“待办”看到 `routine` 类型专题任务。
2. 进入任务详情，确认标题、范围、课件顺序和“无需考试”。注意：任务课件列表目前只对 `rich_text` 显示“图文”，其他类型会显示“HTML”；结构化课件的这个列表标签不准确，但不影响打开后的结构化渲染。
3. 检查每一张图的清晰度、等比显示和失败重试；当前没有点击放大。
4. 在中途退出后重新进入，确认从已确认内容块的下一项恢复。
5. 分别验证随堂题答对、答错、重试，以及情境选择的后果/依据；确认这些不计正式考试。
6. 到最后一项确认后点击“完成本次学习”，完成任务中的全部课件。
7. 提交本人签字，确认任务变为已完成，并在“记录”中显示“日常/年度”而非“三级教育”。
