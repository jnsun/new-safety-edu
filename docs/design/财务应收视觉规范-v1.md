## 0. 与安全生产平台的关系

同一个 logo、同一套色源，但**独立成篇**。财务场景与培训场景的差异决定了配色用法的不同：

| | 安全生产 / 培训 | 财务应收 |
| --- | --- | --- |
| 情绪 | 积极、鼓励学习 | 稳重、可核对、可审计 |
| 主要信息形态 | 卡片、任务行、进度 | **大表格、金额、趋势** |
| 深色侧栏 | 改进项 | **必须**——把彩色留给数据，不留给外壳 |
| 强调色用法 | 引导点击 | **锚定关键数字与异常** |
| 页面底色 | 浅灰白 | 浅灰白 + **米色分区**（借鉴 Ledgery） |

一句话原则：**外壳越安静，数字越响。**

## 1. 设计原则

1. **钱要看得清。** 金额是主角：等宽数字、右对齐、千分位、单位统一标「万元」。任何装饰都不许抢它的对比度。
2. **深色只做壳，不做数据。** 侧栏、深色面板负责承载与分区；一旦进入数据区就是白底深字，保证长时间读表不累。
3. **异常只给橙色，且只给一处。** 橙 = logo 橙 `#E66D1E`，专属「逾期 / 超收 / 核销待调减 / 决算未定」。同一屏不出现两处橙色焦点。
4. **每个语义色两副面孔。** 图形用鲜色（`#E66D1E`），文字用加深版（`#A0500C`）。这条是硬约束，见 §2.4。
5. **状态必须带文字，不能只靠颜色。** 色点 + 文字标签成对出现，色盲用户与黑白打印都能读。

## 2. 色彩系统

### 2.1 色源实测（取自 `公司logo.PNG`）

对 logo 位图做逐半径扫描与纯色像素计数，得到官方色值与几何比例：

| 分片 | 实测色值 | 占非白像素 | 角度范围（从正上方顺时针） |
| --- | --- | --- | --- |
| 青绿主环 | **`#12A289`** | 60.2% | 内圈整环 |
| 黄绿 | **`#BFE81E`** | 10.2% | 外圈 5°–80° |
| 橙 | **`#E66D1E`** | 9.1% | 外圈 85°–160° |
| 深灰 | **`#4F5053`** | 8.7% | 外圈 165°–215° |
| 蓝 | **`#3468A1`** | 9.2% | 外圈 220°–272° |
| 青绿分片 | `#12A289` | — | 外圈 275°–355° |

**几何**（以外半径 R = 1.0 为基准，实测内容包围盒 1360×1360）：

```
中心孔    r = 0 → 0.382R
青绿内环  0.382R → 0.696R   （环厚 0.314R）
环间缝隙  0.696R → 0.807R   （厚 0.111R）
外圈分片  0.807R → 1.000R   （环厚 0.193R）
分片间隙  约 5°（外圈每片 72°，留缝）
```

> 这是个**双环**结构，不是单环分片。上一版（安全生产规范）画的单环是简化示意，本版按实测重绘。

### 2.4 三条硬约束（违反即返工）

1. **`#12A289` 与 `#E66D1E` 只做图形，不做文字。** 需要文字时换 `--fin-brand-text` / `--fin-warning-text`。
2. **黄绿 `#BFE81E` 只出现在深色底上。** 浅底上用黄绿 = 等于看不见。
3. **主按钮 = 黄绿底 + 墨绿字。** 不要退回青绿底白字（3.20:1），那是这套规范最容易犯的错。

### 2.5 用色配比

一屏之内，面积占比建议：

```
白 / 浅灰底   ████████████████████████  60%
深墨绿（壳）   ██████████                24%
中性线面       █████                     12%
品牌青绿       ██                         3%
亮黄绿         █                          1%   ← 最少，但最醒目
语义色（橙等） ▏                           <1%
```

**黄绿占比超过 3% 就说明强调用滥了。**

## 3. 字体与字阶

### 3.1 字体

| 字符集 | 字体 | 说明 |
| --- | --- | --- |
| 拉丁 / 数字 | **Inter** | 标题用 `Semi Bold` / `Bold`；金额必开 `tabular-nums` |
| 中文 | **Noto Sans SC** | 只有 Regular / Medium / Bold 三档实用 |

数字优先用 Inter —— 它的等宽数字对齐质量显著好于中文黑体。

**⚠️ 中文字重只有三档：`400` / `500` / `700`。**
Noto Sans SC 没有真实的 `SemiBold(600)`，所以本规范全文不出现 600，原因有两层：

1. **Figma 侧**：600 会被字重映射表归到 `Medium`（`≤620 → Medium`），设计稿看着是 Medium；
2. **浏览器侧**：字体只注册 400 / 500 / 700 三档时，`font-weight: 600` 会向 `≥600` 的最近档取近似，也就是 **Bold(700)**。

两边一错位，页面就比设计稿重一档。**要 Medium 就明确写 `500`，要 Bold 写 `700`，不要写 600。**
（Inter 有 `Semi Bold`，但它只用于纯拉丁 / 数字串，不进 `Fin/*` 字阶表。）

### 3.2 字阶

| 令牌 | 字号 | 字重 | 行高 | 用途 |
| --- | --- | --- | --- | --- |
| `Fin/Page Title` | 20px | 500 | 28px | 页面标题（「合同台账」） |
| `Fin/Page Desc` | 13px | 400 | 20px | 标题下说明 |
| `Fin/Section` | 15px | 500 | 22px | 区块标题 |
| `Fin/Card Title` | 14px | 500 | 20px | 卡片标题 |
| `Fin/Metric` | 30px | 700 | 36px | KPI 主数字（等宽数字） |
| `Fin/Metric Sub` | 12px | 400 | 18px | KPI 说明 |
| `Fin/Table Head` | 12px | 500 | 16px | 表头（`--fin-muted`） |
| `Fin/Table Cell` | 13px | 400 | 20px | 表格正文 |
| `Fin/Table Cell Bold` | 13px | 500 | 20px | 应余额等关键列 |
| `Fin/Body` | 14px | 400 | 22px | 表单、正文 |
| `Fin/Label` | 12px | 500 | 16px | 表单标签 |
| `Fin/Tag` | 12px | 500 | 16px | 状态标签 |
| `Fin/Micro` | 11px | 400 | 16px | 版本号、修订号 |

行高在 Figma 的 `Fin/*` 样式里编码为**百分比**（1.40 / 1.50 / 1.45 …），不是像素 —— 这样字号改一档时行高跟着等比缩放，不会脱节。上表的像素值是「14 档里最常用的那一档」的换算结果，与百分比一一对应。

**金额一律 `font-variant-numeric: tabular-nums`**，否则 142px 宽的钱列会每行长短不一。

## 4. 形状与空间

### 4.1 圆角

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--fin-r-card` | 14px | 卡片、面板 |
| `--fin-r-panel` | 10px | 内嵌区块、筛选条 |
| `--fin-r-control` | 8px | 按钮、输入框、下拉 |
| `--fin-r-tile` | 6px | 小标签、色块 |
| `--fin-r-pill` | 999px | 胶囊、状态点 |

比安全生产那套整体**小 2px** —— 财务界面信息密度高，圆角太大会显得松散。

### 4.2 间距

以 4 为基数：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48`。

语义映射：

| 位置 | 值 |
| --- | --- |
| 卡片内边距 | 20px（紧凑卡 16px） |
| 卡片之间 | 16px |
| 表单控件之间 | 12px |
| 表格单元格内边距 | 8px 12px |
| 页面内容区 | 24px 左右 / 20px 上 / 32px 下 |
| 区块标题到内容 | 12px |

### 4.3 后台栅格

```
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│  ┌──────────┐  ┌────────────────────────────────────────┐   │
│  │          │  │  顶栏  56px                             │   │
│  │  侧栏    │  ├────────────────────────────────────────┤   │
│  │  208px   │  │                                        │   │
│  │  固定    │  │   内容区  1184px × 24px 内边距          │   │
│  │  深墨绿  │  │                                        │   │
│  │          │  │                                        │   │
│  └──────────┘  └────────────────────────────────────────┘   │
│                                                              │
└──────────────────────────────────────────────────────────────┘
                     1440px
```

- 设计基准 **1440px**，最小支持 1280px（此时侧栏可收起为 64px 图标栏）
- 侧栏 **208px**（比安全生产的 224 窄，因为菜单只有 6–7 项，且要给宽表让位）
- 顶栏 **56px**
- 内容区宽 = 1440 − 208 − 24×2 = **1184px**
- 12 列栅格，列间距 20px（列宽 ≈ 80.33px）—— 与看板卡片的 `w: 12/8/6/4` 直接对应

### 4.4 阴影

只留两级，都很轻（财务界面靠描边分区，不靠阴影）：

```css
--fin-shadow-card: 0 1px 2px rgba(10,46,40,.05), 0 0 0 1px rgba(10,46,40,.04);
--fin-shadow-pop:  0 8px 24px rgba(10,46,40,.12), 0 0 0 1px rgba(10,46,40,.06);
```

**永远不要给表格行加阴影。**

## 5. 数据展示规范（本规范的核心）

### 5.1 金额

- **单位统一「万元」**，在工具栏与汇总条显式标注（`金额单位：万元`），不在每个单元格重复
- 千分位分隔，默认 **2 位小数**；列设置可切 0 / 2 / 4 位
- 负数（超收形成的负余额）用 `--fin-warning-text` + 前置 `-`
- **空值显示 `—`（em dash），不显示 0。** 决算未定时账外应收与应收余额故意留空，不能被渲染成 0
- 金额列一律**右对齐**、等宽数字、列宽固定 **142px**

```css
.fin-money {
  font-variant-numeric: tabular-nums;
  text-align: right;
  font-feature-settings: "tnum" 1;
}
```

### 5.2 大表格

台账一行一合同、默认 22 列，是这套系统最容易做坏的地方。

| 项 | 规格 |
| --- | --- |
| 行高 | 36px（紧凑模式 32px） |
| 表头高 | 40px，`--fin-surface-soft` 底，`12px/500` `--fin-muted` |
| 单元格内边距 | 8px 12px |
| 冻结列 | 前 2 列：财务归属部门、合同编号；右边界加 1px `--fin-line-strong` + 3px 投影 |
| 文本列 | 单行省略；项目名称 / 客户名称 / 对方反馈 / 最新进展 / 下一步计划 **最多 2 行** |
| 金额列 | 右对齐，142px |
| 日期列 | `YYYY-MM-DD`，104px |
| 状态列 | 色点 + 文字标签 |
| 异常行 | 行首 3px 橙色条（`--fin-warning`），悬停时保留 |
| 作废行 | 整行 `--fin-muted` + 删除线，底色 `--fin-neutral-soft` |
| 斑马纹 | 不用斑马纹，用 1px `--fin-line` 横线分隔 |
| 悬停 | `--fin-surface-soft` 底 |

**排序箭头**只在当前排序列显示，未排序列悬停才出现 —— 22 列全带箭头会变成噪声场。

### 5.3 汇总条

表格上方固定一条汇总，与表格同宽：

```
┌────────────────────────────────────────────────────────────────┐
│ 当前筛选范围        应收余额（万元）   到账金额（万元）   开票金额（万元） │
│ 128 条合同            4,286.35          3,914.02           5,102.80   │
│ 以上为服务端对完整筛选范围的汇总，不是当前页求和。                          │
└────────────────────────────────────────────────────────────────┘
```

- 数字用 `Fin/Metric` 的缩小版（22px/700），标签用 `Fin/Label`
- 必须带「不是当前页求和」的说明 —— 财务会算错账就是因为这种歧义

### 5.4 KPI 卡片

看板卡片统一结构：

```
┌──────────────────────────────┐
│ 应收余额（万元）         [⋯] │  ← 12px/500 次要色 + 操作
│                              │
│ 4,286.35                     │  ← 30px/700 tabular-nums
│ 128 条有效台账                │  ← 12px 次要
└──────────────────────────────┘
```

- KPI 卡内边距 **20px**，高度**按内容自适应**（内容高 + 40px），不要写死常量：

  | 卡片形态 | 内容高 | 卡片高 |
  | --- | --- | --- |
  | 两行（标签 14 + 间距 7 + 数值 36） | 57 | **97** |
  | 三行（上面 + 间距 7 + 副行 16） | 80 | **120** |

  ⚠️ 卡片一旦写死高度，内容超高就会**掉到卡外** —— 副行是浅色字（深色卡上的浅绿），
  落到白底上几乎看不见，肉眼极易漏过。**加副行时必须同步加高**。
- 标签行：标签**独占剩余宽度**（标签 FILL、色点靠右），**不要在中间再插弹性占位块** ——
  两者都会抢剩余空间，Figma 按比例对半分。实测「台账数量（条合同）」被压到 94px 而实际需要 104px，被挤成两行。
- 深色 KPI 卡（放在深色分区里）用 `--fin-ink-800` 底 + 白字 + 黄绿数字
- 一个看板最多 **1 张**深色 KPI 卡，其余全白

### 5.5 图表

| 部门 / 客户余额条 | 水平条，底色 `--fin-track`，填充 `--fin-brand`；数值右对齐；条高 6px 圆角 999 |
| 债权状态构成 | 环形，分片色序：青绿 → 蓝 → 橙 → 灰 |
| 趋势线 | 2px 线 + 10% 同色填充；不用点，最后一个点例外（6px 实心圆） |

**图表一律不用渐变**（除深色分区里的面积填充可用 `rgba(191,232,30,.14)` 单向淡出）。

### 5.6 状态与异常

三组状态，各有专属色，**色点 + 文字**成对：

| 组 | 值 | 色点 | 文字色 | 浅底 |
| --- | --- | --- | --- | --- |
| 记录状态 | 有效 | `--fin-success` | `#0B6B4B` | `--fin-success-soft` |
| | 已作废 | `--fin-neutral` | `--fin-muted` | `--fin-neutral-soft` |
| 授权状态 | 有效 / 已撤销 | 绿 / 灰 | 同上 | 同上 |
| 待核对 | 超收 | `--fin-warning` | `--fin-warning-text` | `--fin-warning-soft` |
| | 核销待调减 | `--fin-warning` | `--fin-warning-text` | `--fin-warning-soft` |
| | 决算未定 | `--fin-warning` | `--fin-warning-text` | `--fin-warning-soft` |
| 处理阶段 | 预览中 / 已应用 / 已回滚 | 蓝 / 绿 / 灰 | `--fin-info` / `#0B6B4B` / `--fin-muted` | 对应浅底 |

**「决算未定」不是错误。** 它是业务允许的中间状态，用橙色提示即可，不要用红色警报。

### 5.7 数字锚点

看板与汇总条上，**每屏最多一个黄绿（深底）或墨绿加粗（浅底）的数字**。这是「一眼看到最重要的数」的机制，多了就失效。

### 5.8 键值网格（详情 / 概览）

合同详情抽屉（C 区 74 板）的概览区用它替代 antd 的 `Descriptions bordered size="small"`。
**结构**：一个「段」= 14px/600 段标题 + 8px 间距 + 一张网格；一张网格内固定 2 列。

| 项 | 规格 |
| --- | --- |
| 列数 | 2（每列宽 = 容器宽 ÷ 2） |
| 行高 | **46px 定值** |
| 单元格内边距 | 左右 12px、上下 3px |
| 标签 | 11px / 400 / `--fin-muted` |
| 值 | 13px / **500** / `--fin-ink` |
| 空值 | 显示 `—`，颜色降到 `--fin-muted` |
| 行分隔 | 1px `--fin-line`，贯通整行 |
| 列分隔 | 1px `--fin-line`，只在两列之间 |
| 容器 | 圆角 10px、1px `--fin-line` 描边（`strokeAlign: OUTSIDE`）、底 `--fin-surface` |

**为什么行高必须是定值**：一段里各行的标签 / 值长短不一，行高一旦随内容浮动，整张网格的横向分隔线就会参差不齐，扫读时反而找不到行 —— 详情页靠的是**列对齐**，不是留白。

**空值必须显示 `—`**：财务台账里「决算未定」「尚未开票」这类情况会留空，而留白和「值为 0」在视觉上分不清 —— 这个区别直接对应业务含义。同一条规则也适用于表格里的金额列（§5.1）。

## 6. 组件规范

### 6.1 按钮

| 变体 | 底色 | 文字 | 描边 | 用途 |
| --- | --- | --- | --- | --- |
| Primary | `--fin-accent` 黄绿 | `--fin-accent-ink` | 无 | 每屏最多 1 个主操作 |
| Primary Dark | `--fin-ink-900` 墨绿 | 白 | 无 | 深色分区里的主操作 |
| Secondary | 白 | `--fin-ink` | `--fin-line-strong` | 取消、次要 |
| Ghost | 透明 | `--fin-brand-text` | 无 | 表内文字操作 |
| Danger | 白 | `--fin-danger` | `--fin-danger` 30% | 作废、撤销、回滚 |

- 高度：32px（表格内 28px）
- 内边距：0 14px；圆角 8px
- 字号 13px/500
- **Primary 全屏只出现一个** —— 财务界面里两个黄绿按钮会让人不知道该点哪个

### 6.2 状态标签

- 高 22px，圆角 6px，内边距 0 8px，字号 12px/500
- 浅底 + 同色系文字（见 §5.6 表）
- 可带 6px 圆点；圆点在左、文字在右
- **禁用态用灰色标签，不用降低透明度** —— 半透明标签在表格里会看不清

### 6.3 胶囊筛选器

沿用平台的胶囊交互（不用下拉），但财务场景多加一条：

- 高 28px，圆角 999，内边距 0 12px，字号 13px
- 未选：白底 + `--fin-line-strong` 边 + `--fin-ink-soft` 字
- 已选：`--fin-ink-900` 底 + 白字
- **已生效筛选必须在筛选条下方以胶囊形式回显，可单独关闭** —— 22 列的表，用户必须一眼知道现在被筛掉了什么

### 6.4 表单

- 标签在上（`Fin/Label`），控件在下
- 控件高 32px，圆角 8px，底色白，描边 `--fin-line-strong`
- 聚焦：描边 `--fin-brand`，外加 `0 0 0 3px rgba(18,162,137,.14)`
- 必填标记用 `*` 前置 `--fin-warning`
- 错误：描边 `--fin-danger` + 控件下方 12px 红字
- **金额输入框右对齐 + 等宽数字**，右侧内嵌单位「万元」

### 6.5 侧栏导航

- 宽 208px，底 `--fin-ink-900`，无描边
- 顶部品牌区：logo 反白 + 「财务应收 / 账款管理」两行，高 60px
- 菜单项高 40px，圆角 8px，内边距 0 12px，字号 13px
- 图标 16px，与文字间距 10px
- **未选**：字色 `--fin-on-ink-2`，图标 `--fin-on-ink-3`
- **选中**：底 `--fin-accent` + 字 `--fin-accent-ink` + 图标同字色
- **悬停**：底 `rgba(255,255,255,.07)`

选中项用黄绿实底，是整套规范里呼应最强的视觉锚点：**「你现在在这里」。**

### 6.6 空态与错误态

| 态 | 表现 |
| --- | --- |
| 加载 | 骨架屏（表格用 8 行灰条），不用转圈 |
| 无数据 | 居中图标 + 「当前筛选下没有台账记录」+ 一个「恢复默认筛选」按钮 |
| 无权限 | 403 图标 + 「当前账号没有此项管理权限」，**不显示任何数据碎片** |
| 读取失败 | 「数据加载失败，已隐藏缓存内容」+ 重试按钮 —— 必须明说「已隐藏缓存」，财务数据不能显示旧值 |
| 版本冲突 | 黄色警示条 + 本地草稿 / 服务端最新值对照 + 二次确认勾选 |

### 6.7 页内分段导航（Tabs）

这一节是画 C 区时补的 —— 原规范只定义了筛选胶囊，没说「切换视图」该长什么样。**两者必须能一眼分开：**

| | 页内分段导航（Tabs） | 筛选胶囊（§6.3） |
| --- | --- | --- |
| 语义 | 我在看哪一屏 | 我在看哪些数据 |
| 形态 | 文字 + **下划线**，无底色 | **胶囊**，有底色有描边 |
| 选中 | 13.5px / 500 / `ink-900` + **2px** `ink-900` 下划线 | 13.5px / 500 / 白字 + `ink-900` 实底 |
| 未选 | 13.5px / 400 / `muted` + 1px `line` 下划线 | 13.5px / 400 / `ink-soft` + 1px `line-strong` 描边 |
| 尺寸 | 高 34，项间距 28 | 高 28，内边距 0 12 |

**禁止把 Tabs 做成胶囊。** 混用之后用户分不清「点了会切换界面」还是「点了会筛掉数据」——这在财务系统里是会出事的歧义。

应用位置：数据处理（新增记录 / Excel 导入 / Excel 导出）、合同详情抽屉（合同概览 / 开票明细 / 回款明细 / 附件 / 修订历史）。

- 选项卡按权限逐项出现，无权限的项**直接不渲染**，置灰一个不能用的标签没有意义。
- 抽屉里的选项卡同样按权限裁剪。

## 7. Logo 应用

按 §2.1 实测几何重绘，**双环结构**。

### 7.1 四种处理

| 场景 | 处理 | 尺寸 |
| --- | --- | --- |
| 深色侧栏 | 反白：内环与外圈分片全填 `#FFFFFF`，保留环间缝隙 | 28–32px |
| 登录页 / 打印页眉 | 彩色原样 | 72–160px |
| 浏览器 favicon | 去掉外圈分片，只留青绿内环 + 缝隙 | 32×32 |
| ≤24px（如页脚） | 同上，仅青绿内环 | 16–24px |

### 7.2 留白与最小尺寸

- 四周最小留白 = **外径 × 30%**（比安全生产的 25% 略大，财务场景更克制的观感）
- 彩色完整版最小 **40px**；低于此尺寸只保留青绿内环
- 深底反白版最小 **24px**

### 7.3 禁止用法

1. 拉伸 / 压扁（必须等比）
2. 旋转任意角度（外圈分片的角度是品牌资产）
3. 加投影 / 发光 / 描边
4. 改分片色相（黄绿不能换成青绿）
5. 把外圈分片拆开当装饰图形
6. 在彩色底上贴彩色 logo（浅底才配彩色版）
7. 用 logo 做平铺水印

### 8.3 三处容易做错的业务语义（改 UI 时必须守住）

设计稿是按代码逐行核对画的，这三处最容易被「想当然」改反：

1. **「更新现有台账」= 只补充当前为空的字段，不是覆盖。**
   `receivables-types.ts` 与 `apps/api/src/receivables-import.ts:310`（「重复导入只补充台账空字段，期初开票和到账明细不会重复写入」）两处印证。把它写成「覆盖」会造成数据事故。

2. **导入向导的 5 个阶段是派生的，不是「上一步/下一步」推的。**
   `receivablesImportStage()` 从 `preview` + `decisions` + `confirmed` 推导；只要有一条重复行未选决定，`unresolvedDuplicate` 就让它停在「重复决策」。
   所以这一步**没有**「下一步」按钮，只有「放弃本次预览」。各阶段的操作按钮分别是：`duplicate_decisions` → 放弃本次预览；`impact_preview` → 进入最终确认；`confirm_apply` → 确认应用。

3. **只读态与操作条互斥。**
   抽屉标题右侧的「只读」标签只在 `!capabilities.canWriteLedger` 时出现，而那种情况下操作条里一个按钮都不会渲染。画成「只读 + 还能编辑」是自相矛盾的。
