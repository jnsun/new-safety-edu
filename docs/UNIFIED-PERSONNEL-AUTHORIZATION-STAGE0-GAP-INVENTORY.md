## 1. 本阶段边界

本阶段只读取代码、数据库结构、迁移、现有检查脚本和界面实现，不修改业务代码、数据库、账号、人员、角色或生产权限。

本阶段回答三个问题：

1. 当前实现中哪些能力可以保留；
2. 哪些实现与已确认目标直接冲突；
3. 进入数据模型和鉴权改造前，还必须从目标环境读取哪些匿名汇总与异常清单。

本文件不是实施完成证明，也不代表现有静态检查通过就符合新基线。现有检查验证的是旧规则，其中有些检查恰好把本轮需要整改的行为当作正确行为。

## 2. 执行摘要

当前系统已经具备“人员与账号分离、一个人员至多绑定一个账号、服务端统一访问数据库、按人员加载安全角色、角色和组织关系保留历史、项目结束不可恢复”等可复用基础，不需要推倒重建。

但目标权限模型尚不能直接上线，已确认存在以下五类关键风险：

- **明确越权**：财务资产部普通成员无明确授权仍自动获得全部应收只读；组织或项目管理员可以读取、导出完整敏感资料；财务负责人和管理员仍有业务物理删除附件能力。
- **权限可能复活**：停用人员时安全角色会结束，但财务授权不会结束；人员和账号重新启用后，旧财务授权可能重新生效。
- **授权主体错误**：应收授权仍绑定账号，并会为没有账号的人员自动创建待激活账号，不符合“授权给人员、账号只是登录凭据”。
- **角色和能力粒度不足**：没有安全生产业务管理员能力包，没有项目经理与项目安全员的独立职责，也没有报账员字段级写入白名单。
- **第一版范围未收口**：外协和临时人员的注册、建档、审批、项目加入及身份变更服务仍可执行，并非只保留未启用的数据库类型。

因此，当前结论不是“可以直接按新规则使用”，而是“底层身份基础可复用，但必须先完成权限模型和高风险边界整改”。

## 4. 必须整改的缺口

优先级定义：

- `P0`：现有行为可能造成越权、敏感数据暴露、权限复活或第一版范围突破；实施时先封口。
- `P1`：目标模型不可缺少的结构或服务端规则；没有它就无法按已确认矩阵授权。
- `P2`：解释性、复核、通知和界面收口；不应遗漏，但可在核心拒绝规则稳定后完成。

## 5. 当前数据盘点状态

### 5.1 已确认的连接状态

- 工作区只有 `.env.example`，没有本地 `.env`。
- 当前进程没有 `DATABASE_URL`。
- 因此没有连接任何测试或生产数据库，也没有读取任何人员、账号或财务业务数据。
- 本节不能给出实际数量；所有数量均保持“待目标环境只读核验”。

### 5.2 目标环境必须输出的匿名汇总

执行时只输出 ID、状态、角色、scope 和计数；人员姓名、手机号、身份证、财务金额和附件内容不进入盘点文件。

| 清单 | 必查项 | 处置原则 |
| --- | --- | --- |
| 人员 | 按 `type/status` 计数；active 外协/临时人员 ID | 第一版上线前逐项人工决定停用或保留为历史，不自动删除 |
| 账号 | 未绑定人员、绑定非 active 人员、pending/disabled/merged 账号、同一自然人疑似多账号 | 进入“登录与绑定异常”，不根据姓名自动合并 |
| 组织 | 无主组织、多个 active 主组织、非正式员工主组织、负责人缺位或重复 | 违反数据库约束的先阻断迁移；业务缺位进入人工处置 |
| 安全角色 | 无 `personId`、主体非 active 员工、scope 不存在、角色与组织资格不符、停用人员仍有当前角色 | 当前授权只列清单，不自动猜测归属 |
| 项目 | ended 项目仍有 active 成员/职责、普通部门人员担任项目职责、每项目当前管理员数量 | 映射到新经理/安全员前由业务负责人确认职责类型 |
| 财务授权 | 同一账号多份当前授权、账号无人员、人员非 active、停用人员仍有授权、财务部普通成员依赖隐式只读 | 先导出冲突；迁移到人员授权前逐项裁决 |
| 财务配置 | `financeOrganizationId` 是否存在且指向 department；是否仍依赖名称回退 | 不允许按名称自动绑定 |
| 敏感导出 | 最近导出任务的请求人角色、scope、类别、状态和 hash 是否齐全 | 只核对元数据，不打开导出文件 |
| 财务附件 | 物理删除审计动作数量、作废数量、缺失文件数量 | 不恢复、不清除；形成受控处置清单 |
| 权限复核 | 当前公司管理员、财务负责人、财务管理员、高敏导出人员 | 作为首批半年复核基线；不得推断历史复核日期 |

### 5.3 数据盘点停止条件

遇到以下任一情况立即停止写入式迁移，只输出冲突清单：

1. 一个账号绑定不到唯一人员；
2. 一个人存在多份当前财务授权；
3. 财务负责人不能由唯一稳定组织 ID 派生；
4. 一个组织存在多个当前负责人；
5. active 角色的主体、scope 或业务对象已经不存在；
6. 发现已停用人员仍可登录或仍有当前财务访问；
7. 旧 `project_admin` 无法由现有事实判断应迁移为项目经理还是项目安全员。
